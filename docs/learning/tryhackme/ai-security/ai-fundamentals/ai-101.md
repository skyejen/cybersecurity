## :material-laptop: What I did / learned { data-toc-label="What I did / learned" }

### The nesting doll

AI > Machine Learning > Deep Learning > LLMs. Each one lives inside the one before it (matryoshka, anyone?).

- AI - the whole field: getting machines to do things that normally need human reasoning. Around since the 1950s, mostly academic until ML came along.
- ML - the machine learns from data instead of someone hand-writing the rules.
- Deep Learning - ML using neural networks with lots of layers.
- LLMs - deep learning models built on transformers, trained on a ridiculous amount of text.

### How ML learns

The ML lifecycle: define the problem, collect and clean data, train, evaluate and tune, deploy, then monitor and retrain forever (like a continuous loop).

Under the hood every algorithm does the same thing on repeat: make a prediction, measure how wrong it was, adjust, go again.

Four types:

- Supervised - trained on labelled data (this email is spam, this one isn't).
- Unsupervised - no labels, it finds its own groups and patterns (useful for spotting weird network traffic).
- Semi-supervised - a few labels guiding a big pile of unlabelled data, for when labelling is expensive.
- Reinforcement - an agent tries things and gets rewarded or penalised (game-playing AI).

Overfitting - the model memorises its training data instead of learning the pattern, so it falls over on anything new. Basically the student who memorised last year's exam paper. This comes back later as a security problem, because memorised data can leak.

### Neural networks

Loosely modelled on the brain: layers of nodes (neurons) joined by weighted connections (synapses).

- Input layer - takes the raw data. A 4x4 pixel image means 16 input nodes.
- Hidden layers - pull out features, simple ones first (edges, curves), then more complex ones deeper in.
- Output layer - the answer. For handwritten digits, one node per digit and the highest score wins.

Training is just tuning those weights. More than three layers counts as deep learning.

The big deal about deep learning is that it works out its own features from raw data, so nobody has to hand-pick what to look at. The boom happened when the internet digitised everything and suddenly there was enough data (and GPU power) to feed it.

!!! note "Double-checked"

    The room says deep learning doesn't need labelled data. That's a bit of a simplification: plenty of deep learning is still supervised (image classifiers are usually trained on labelled images). What deep learning removes is the need for humans to hand-engineer the features.

    But also as a note for me, helpful for revision! (especially when I will be prepping for the final exam^^)

### LLMs

An LLM predicts the next token, then the next, then the next, until the reply is done (even though sometimes it feels like black magic!).

- Pre-training - hide the last word of some text, let the model guess, compare with the real answer, and nudge the parameters with backpropagation. Repeat trillions of times.
    - Backpropagation - the error gets passed backwards through the layers to work out how much each weight contributed to the wrong answer, and each one gets tweaked a little. Blame assignment, but for maths.
- Transformers - the architecture from Google's 2017 paper "Attention Is All You Need". They process text in parallel instead of word by word, which is what made training at this scale possible.
- Attention - works out which words matter to each other. In "Buggy dropped the ball because it was soggy", attention is how the model works out "it" is the ball (not Buggy, even if he is also soggy).
- Reinforcement Learning from Human Feedback (RLHF) - humans rate outputs after pre-training, which turns a raw text predictor into something that behaves like an assistant.

### How AI gets attacked

MITRE ATLAS is basically ATT&CK for AI: attacker tactics and techniques mapped specifically for AI systems.

The five vulnerabilities to know:

| Vulnerability | What it is |
|---|---|
| Prompt injection | User input overrides the model's instructions (its system prompt) |
| Data poisoning | Tampering with training data so the model learns the wrong thing, e.g. a spam filter trained to let spam through |
| Model theft | Stealing the model, or cloning it by hammering its API and training a copy on the answers |
| Privacy leakage | Sensitive training data gets baked into the weights and can come back out with the right prompt |
| Model drift | The world changes, the model doesn't, and performance quietly degrades |

### AI as the attacker's power tool

Same old attacks, but now AI-powered:

- Malware - generative AI lowers the skill bar and speeds up iteration.
- Deepfakes - fake voice or video of a real person. The infamous "CEO" voice message asking finance for an urgent wire transfer.
- Phishing - "spot the bad grammar" is dying as a red flag, because AI writes fluent, targeted emails at scale... funnily enough, too-perfect writing can now be the new giveaway :D

### AI for the defenders

Where AI helps the blue team: analysis (spotting anomalies in logs and traffic), prediction (e.g. catching phishing before it lands), summarisation (turning a mountain of alerts and reports into a brief) and investigation (explaining logs, suggesting queries, threat hunting ideas).

!!! note "Double-checked"

    The IBM numbers in the room ($4.88M average breach cost, $2.2M saved with AI, 108 days faster containment) are from IBM's 2024 Cost of a Data Breach report. The newer editions have moved on: the 2026 report puts the global average at $4.99M. The takeaway (AI-assisted teams find and contain breaches faster and cheaper) still stands. Latest report: [IBM Cost of a Data Breach](https://www.ibm.com/reports/data-breach).

### Securing AI

- Lock down who can talk to the model: authentication, RBAC (Role-Based Access Control: permissions hang off roles like "analyst" or "admin" rather than individual people), MFA.
- Treat training data like any other sensitive asset: audit it, minimise it (only collect and keep what the model actually needs, so there's less to leak), encrypt it.
- Follow AI-specific standards, e.g. ISO/IEC 27090 (guidance on AI security threats).
- Monitor the model. Weird outputs or sudden drift can be an attack in progress. SHAP and LIME are explainability tools that show why a model gave the answer it did (note to self: look into it properly...).

!!! note "Double-checked"

    ISO/IEC 27090 was still at final draft stage when I checked (September 2026), so it isn't an official published standard yet.

## :material-lightbulb-on-outline: Key takeaways { data-toc-label="Key takeaways" }

- LLMs are next-token predictors built on transformers and shaped by RLHF. Knowing that makes most of their weird behaviour make sense.
- AI brings its own vulnerability class (prompt injection, poisoning, theft, leakage, drift), and MITRE ATLAS is the map.
- The same tech makes attackers faster and defenders faster. Securing it from day one is what decides which side wins.
